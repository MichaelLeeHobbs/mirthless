## Decisions I made

1. **Nothing is Accepted.** Every row is Proposed. Replaced rows keep their text, because the format allows `Superseded by` only once the replacement is Accepted: the new row's source note says "Replaces X", and accepting it supersedes X. Replaced rows are marked "already rewritten" below and need no answer.
2. **Debate rewrites got new IDs**, as you asked, instead of editing in place. Three exceptions were edited in place, which the format allows for Proposed rows: the priority of seven rows (AUTH-MFA-02, -03, -04, -05, -06, CONN-NEW-05, CONN-FILE-05), the TypeScript blocks of interfaces/connector.md (new planned members), and the fixes of the fresh-context review, which touched about 45 rows and notes across the areas to remove contradictions between them.
3. **Areas**: 16, grouped by what a user would recognise, plus the connector interface with its own code `CPI`. You were not asked to confirm them first, as the skill would.
4. **Guide of 15 to 35 rows per area**; most went over: Authentication, Connectors and the interface by design, then Pipeline, Scripting, Channels, Mirth migration, Operations, Monitoring, Access control, Audit and Messages. P1 is heavy (549 of 790, replaced rows counted) because message safety, PHI and access rules were all written P1. 5. **Conflicts between sources** were settled as Appendix C lists: the later decision or the safer rule, always named in the row's source note.
6. **Out of scope** holds the six Won't rows of capabilities.md and the non-goals of docs 09, 14, 18 and 20. The lines that cite only doc 14 are its recommendations, not decisions (the README says so): confirm or strike them. More candidates are in Appendix D.

The Authentication, Access control, Audit and Security tables below say nothing about what is built.

### Connector plugin contract interface ([interfaces/connector.md](interfaces/connector.md))

| **ID** | Requirement | Recommendation | Reason |
|---|---|---|---|
| CPI-RES-01 (P1) | Every method of a connector that returns a promise, and every `MessageDispatcher` the engine supplies, shall resolve to a `Result` and shall never throw or reject; the exceptions are `onMessageDelivered`, whose rejection CPI-SRC-06 defines, and the factories of CPI-REG-01. | **Accept** | Built. A thrown send or stop escapes the status, queue and alert handling; every connector already wraps its methods. |
| CPI-RES-02 (P1) | When a connector throws, rejects or resolves to anything that is not a `Result`, the engine shall treat that one call as `{ ok: false }` with code `INTERNAL`, and the outcome of the same message at its other destinations, and every other channel, shall be what it would have been without the fault. | **Accept** | Partly built. | CPI-RES-03 (P2) | The `error` of every `{ ok: false }` a connector returns shall carry one `code` from `ConnectorErrorCode`, and the same failure shall carry the same code in every connector: `CONFIG_INVALID` for settings, `UNREACHABLE` when no connection was made, `AUTH_FAILED` when the partner refused the credentials, `TIMEOUT` when a time limit passed, `ABORTED` when `signal` or `onHalt` ended the call, `NOT_STARTED` for a call before `onStart`, `PERMISSION_DENIED` when the partner or the file system refused the action, `PROTOCOL_ERROR` for an answer that cannot be read, `INTERNAL` otherwise. | **Rewrite** | Not built.
